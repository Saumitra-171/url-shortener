# URL Shortener

A URL shortener API with user accounts, click analytics, and Redis caching, built with FastAPI, PostgreSQL, and Redis.

## Features

- Shorten URLs and redirect with a `302`, so every visit is counted
- JWT authentication: register, log in, and manage your own links
- Ownership checks: only the creator can view analytics for or delete a link
- Click analytics: total clicks, last click time, and recent clicks with referrer and user agent
- Redis cache on the redirect path that fails soft: if Redis is down, the app falls back to Postgres
- Rate limiting with a Redis sliding window: per user on link creation, per IP on register and login
- Custom aliases and link expiry (expired links return `410 Gone`)
- Asynchronous click recording: redirects queue a click in Redis and a background worker writes them in batches, with retries and a dead-letter queue
- Alembic migrations for reproducible schema changes
- Automated tests with pytest, using in-memory SQLite and a fake cache, so they never touch real data

## Getting started

### Prerequisites

- Python 3.12
- A hosted PostgreSQL database, for example a free [Supabase](https://supabase.com) project. Copy its connection string.
- A hosted Redis database, for example a free [Upstash](https://upstash.com) database. Use the `rediss://` URL (with TLS).

No local database or Docker installation is needed. Note that free tiers may pause or delete inactive databases. If the app suddenly can't connect after a quiet period, check the provider's dashboard.

### Setup

```powershell
git clone https://github.com/Saumitra-171/url-shortener.git
cd url-shortener
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
```

Copy `.env.example` to `.env` and fill it in:

```
APP_NAME=URL Shortener
BASE_URL=http://localhost:8000
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME
REDIS_URL=rediss://default:PASSWORD@HOST:6379
SECRET_KEY=<generate one, see below>
```

Generate a secret key (it signs login tokens, so keep it private):

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Create the database tables and start the server:

```powershell
alembic upgrade head
uvicorn app.main:app --reload --reload-dir app
```

Interactive API docs are at http://localhost:8000/docs.

## API

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/auth/register` | no | Create an account |
| POST | `/auth/login` | no | Get an access token (form fields `username` and `password`) |
| GET | `/auth/me` | yes | Current user |
| POST | `/shorten` | yes | Create a short link (optional `alias` and `expires_at`) |
| GET | `/{short_code}` | no | Redirect to the original URL (`410` if expired) and queue a click |
| GET | `/{short_code}/analytics` | yes, owner | Click statistics |
| DELETE | `/{short_code}` | yes, owner | Delete a link and its clicks |
| GET | `/health` | no | Health check |

### Example

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8000/auth/register -ContentType "application/json" -Body '{"email": "me@example.com", "password": "password123"}'
$t = Invoke-RestMethod -Method Post -Uri http://localhost:8000/auth/login -Body @{username="me@example.com"; password="password123"}
$h = @{Authorization = "Bearer $($t.access_token)"}
Invoke-RestMethod -Method Post -Uri http://localhost:8000/shorten -Headers $h -ContentType "application/json" -Body '{"url": "https://example.com"}'
```

## Running the tests

```powershell
python -m pytest -v
```

The tests use an in-memory SQLite database and a fake cache, so no Postgres or Redis is needed.

## Database migrations

```powershell
alembic upgrade head                                  # apply all migrations
alembic revision --autogenerate -m "describe change"  # create a migration from model changes
alembic downgrade -1                                  # undo the last migration
```

Always read an autogenerated migration before applying it.

## Design notes

- **302, not 301.** A permanent redirect gets cached by browsers, so repeat visits would never reach the server and clicks would go uncounted.
- **Unique codes via the database.** A random code is inserted and a collision is handled with a retry. Checking first and inserting second would be a race condition.
- **Ownership lives in the query.** Someone else's link and a missing link both return `404`, so the API doesn't reveal which codes exist.
- **Fail-soft cache.** Cache errors are treated as misses and Redis calls have short timeouts, so a Redis outage slows the app down instead of breaking it.
- **Sliding-window rate limit.** Requests are stored in a Redis sorted set, which avoids the burst a fixed window allows at the boundary. If Redis is down the limiter fails open.
- **Expiry is enforced twice.** The cache TTL is capped at the time remaining, and the cached entry also carries the expiry time, which is checked on every hit.
- **Clicks are eventually consistent.** The redirect only pushes an event to Redis. A worker thread batches events into one transaction, retries with exponential backoff, and parks failing batches in a dead-letter list. If Redis is unavailable the redirect writes the click directly. Set `RUN_CLICK_WORKER=false` to disable the worker (the tests do this).
